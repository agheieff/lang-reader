# Optional neural speech: Qwen3-TTS

The reader always works with the browser's own speech voices. This extra adds cached,
neural audio from `Qwen3-TTS-12Hz-0.6B-CustomVoice` (about 5 GB with PyTorch) generated by an
audio worker and stored next to the lessons.

```bash
extras/tts-qwen/install.sh cuda   # NVIDIA GPU
extras/tts-qwen/install.sh rocm   # AMD GPU (pinned ROCm 7.2.1 wheels, Python 3.12, x86_64)
extras/tts-qwen/install.sh cpu    # works, but takes minutes of CPU per lesson
```

The runtime lives in `<data dir>/tts/qwen` with its own virtual environment; the main
application never imports it. `./run.sh` starts one audio worker when the runtime is ready.
Set `ARC_LANG_TTS_ENABLED=0` to leave it off.

* Voices: nine fixed presets; languages Chinese, English, Japanese, Korean, German, French,
  Russian, Portuguese, Spanish, Italian. No voice cloning (out of scope).
* GPU tuning (read by `qwen_provider.py` only): `ARC_LANG_TTS_ATTENTION` (`eager` default or
  `sdpa`) and `ARC_LANG_TTS_DTYPE` (`float32` default or `float16`). The defaults are the
  conservative choice; one AMD RDNA4/ROCm stack crashes in the faster FP16 path, so try
  `sdpa` + `float16` only after a smoke test on your machine.
* Licence: the `qwen-tts` package and the model weights are third-party and downloaded at
  install time; nothing is bundled. Check their licences before redistributing audio.
* Audio format: set `ARC_LANG_AUDIO_FORMAT=opus` on the machine that owns the lessons to store
  compressed audio (needs `ffmpeg` with libopus). The setting accepts `wav` or `opus`; MP3 is
  available only through `lang audio compress --format mp3`, which converts an existing cache
  (older Safari versions cannot play Opus).

## Synthesizing on another machine

An always-on host can keep the queue while a stronger machine synthesizes:

1. On the host set `ARC_LANG_TTS_REMOTE=1` (the reader then reports audio as queued).
2. Choose how the worker reaches the host's queue:
   - **HTTP (recommended).** On the host set `ARC_LANG_AUDIO_WORKER_TOKEN` (or `_FILE`) to a long
     random secret; that enables `/api/audio-worker/` for callers presenting it as a bearer token,
     and nothing else is opened (put the host name in `ARC_LANG_ALLOWED_HOSTS` if it is not
     loopback, and serve it over TLS). On the machine with the runtime set `ARC_LANG_REMOTE_URL`
     (the host's base URL, including `/lang` if it is served under a path) and
     `ARC_LANG_REMOTE_TOKEN` (or `_FILE`).
   - **SSH.** Set `ARC_LANG_REMOTE_HOST` (the ssh target of the host) and `ARC_LANG_REMOTE_CLI` (the
     command that runs the host's `lang` CLI, for example
     `cd /srv/lang && ARC_LANG_DATA_DIR=/srv/lang-data .venv/bin/python -m server.cli`).
3. On the machine with the runtime run `uv run python -m server.remote_tts_worker`.
   `extras/tts-qwen/lang-tts-remote.service` is a systemd user unit for it.

The worker claims one task at a time (`POST /api/audio-worker/claim`, or `lang tts claim` over
SSH), synthesizes, and uploads the WAV (`.../complete`, or `lang tts complete`). Each claim has a token; complete, fail and release must present
it, and a claim left for 45 minutes returns to the queue without charging an attempt.
Upgrade the host and the worker together.
